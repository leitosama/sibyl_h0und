# 0011. Шпаргалка Nextron — источник TI, а не детектор

- Статус: Принято
- Дата: 2026-10-06
- Источник: PR #16, #17, коммиты 7898da2, 1769064

## Контекст

Таблицы Location, User Context и Form / Type из шпаргалки Nextron (Antivirus
Event Analysis Cheat Sheet v1.12) стали первыми `ScoreRule`. Шпаргалка
написана для файлов, на которые сработал антивирус. Проигрывание трейсов
показало, что на образах процессов полная шкала срабатывает на
доброкачественных задачах так же часто, как на ошибочных: админская или
сервисная учётка есть у большинства процессов. `scripts/score_cited.py`
показал, что высокая оценка есть у 22 из 38 верных malicious и только у 2 из
36 ошибочных benign.

## Решение

- Для процессов все оценки сдвинуты на ступень вниз, `C:\Windows\…` для
  образа — 0. Флаг ставится только когда оба атрибута на верхней ступени.
- Для файлов пороги `medium` от 3, `high` от 4. Сумма и пороги — наш выбор,
  калибруются на трейсах.
- Nextron ранжирует то, что уже названо подозрительным, и подтверждает выбор
  модели, но сам подозрительное не находит. Находить должны правила-детекторы
  по командной строке, связям и сети.

## Рассмотренные варианты

- Полная шкала шпаргалки для процессов: шум на benign-задачах.
- Отказаться от Nextron: теряем полезное ранжирование громких находок при
  лимите флагов.

## Последствия

- Исправлять ошибочные benign нужно другими источниками (см.
  [wrong-patterns.md](../wrong-patterns.md)).
- Атрибуты Time и System (роль хоста) не используются, пока не появится
  способ взять роль хоста без лишних вызовов.
