# 0017. Знания — словарь для модели, а не правила-детекторы

- Статус: Принято
- Дата: 2026-10-06
- Источник: обсуждение issue #20; заменяет [0010](0010-advisory-flags.md) и [0011](0011-nextron-as-ti.md), развивает [0012](0012-knowledge-packs.md)

## Контекст

Флаги из ADR 0010 — это наши правила: мы смотрим на данные `practice`, решаем,
что подозрительно, и записываем шаблон с уровнем (`medium`, `high`). Три
источника за одну сессию показали, что это не работает как знание:

- Правило «`original_filename` пакета ATT&CK не совпадает с именем образа»
  — это приём T1036.003 (Masquerading: Rename Legitimate Utilities), записанный
  нами как детектор после того, как мы увидели переименованный SDelete. Он
  подогнан под виденные задачи и не переносится на другие.
- Правила `tampering` (`sqlcmd … UPDATE`, `-replace`, входящие к `svchost`)
  вообще не опираются на источник: это наше чтение трейсов.
- Уровни, пороги, лимит в 5 узлов и сдвиг оценок Nextron «на ступень вниз»
  выбраны нами по 53 ошибочным задачам. Это псевдодетерминированный
  классификатор, поверх которого сидит LLM, а не агентная система.

Идея агента — соединить модель с внешним знанием (как MCP или RAG), не решая
за неё, что хорошо, а что плохо. Модель уже знает ATT&CK; ей нужно не
срабатывание, а справочник, по которому можно проверить догадку.

## Решение

- Знания — словарь. Модель сама решает, что в уликах странно и что искать.
  Код ничего не оценивает: нет уровней, порогов, лимита флагов и триггеров по
  свойствам конкретных сущностей.
- Словарь отдаёт локальный инструмент `lookup_knowledge`. Он добавляется к
  каталогу задачи рядом с инструментами runtime и отвечает локально, как
  GraphLedger: вызов runtime не тратится. Если runtime уже объявил инструмент
  с таким именем, побеждает runtime (ADR 0003).
- Запрос — одна строка: имя файла, `original_filename`, домен, имя инструмента,
  id техники (`T1036.003`) или слова («rename system utility»). Совпадение
  ищется одинаково для любого запроса, без правил по свойствам: нормализованное
  имя, домен и его родительские домены, id, пересечение слов.
- Ответ — записи источников как есть, с указанием источника: ATT&CK
  (техники и ПО), LOLBAS, GTFOBins, GTFOArgs, LOLRMM, WTFBins, шпаргалка Nextron. Без вердикта,
  уровня и сортировки по «важности». Пустой ответ говорит прямо: записей нет,
  это не признак безопасности.
- Модель узнаёт о словаре из описания инструмента в каталоге и из промпта.
  Промпт не называет приёмов; он задаёт метод: назвать технику ATT&CK, которой
  была бы странность, и проверить её по словарю. Текст промпта обсуждаем в
  issue.
- `FlagBoard`, правила, `rank_flags`, события `flags` и ответы с `flags` из
  кода убираем. Старые трейсы с событиями `flags` читаются по-прежнему
  ([0008](0008-traces-outside-repo.md)).
- Пакеты знаний и их сборка остаются ([0012](0012-knowledge-packs.md)),
  добавляются пакеты техник ATT&CK и WTFBins. Шпаргалка Nextron даёт строки
  таблиц как есть: без суммы, без сдвига оценок и без поправки для системных
  каталогов.
- Замер: офлайн проверяем только словарь (`scripts/replay_knowledge.py`: какие
  сущности виденных задач находит запрос, ошибочные против прочих). Влияние на
  вердикты видно только на `practice`.

## Рассмотренные варианты

- Оставить флаги, но показывать факты без уровня: триггер остаётся нашим
  правилом, подогнанным под виденное.
- Автоматически прикладывать совпадения к ответам runtime: то же, плюс шум в
  каждом ответе. Модель сама решает, когда справиться со словарём.
- Только промпт, без файла: знание ATT&CK у модели есть, но проверить
  догадку по тексту источника (LOLBAS, LOLRMM, WTFBins) она не может.

## Последствия

- Исправление ошибочных benign теперь зависит от того, станет ли модель
  обращаться к словарю. Это проверяется прогонами `practice`, не CI.
- Запросы к словарю считаются локальными ответами и подчиняются защите от
  зацикливания ([0015](0015-runtime-call-ceiling.md)): 20 запросов подряд без
  вызова runtime переводят модель в режим «только отчёт». Для расследования
  этого достаточно; больше — признак цикла.
- Правило слияния нового источника — `replay_knowledge.py --compare` против
  `main` и тесты на его запросы, а не `replay_flags.py --compare`.
- WTFBins даёт доказательство «доброкачественно, но выглядит плохо»; решать,
  веско ли оно, остаётся модели.
