# 0007. Модель получает только новые улики

- Статус: Принято
- Дата: 2026-10-05
- Источник: PR #13 (issues #6, #11), коммит df8e15e

## Контекст

Runtime в каждом ответе повторяет алерт и весь каталог инструментов
(~48 КБ), а новое кладёт только в `last_tool_result`. Базовый агент дописывал
весь ответ в историю, и задача съедала 0.2–1.3 млн токенов.

## Решение

Алерт и разобранный каталог идут в первое сообщение один раз. После каждого
вызова в историю попадают только статус, `last_tool_result` целиком и
ошибка. `reward` модели не показывается (см.
[0006](0006-step-reward-offline-only.md)). В трейсе `llm_call` хранит только
сообщения после общего с прошлым запросом префикса,
`trace.llm_requests` восстанавливает полные запросы.

## Рассмотренные варианты

- Обрезать или суммировать историю: теряет улики, на которые потом нужно
  сослаться в отчёте.

## Последствия

- Если runtime начнёт присылать в ответе что-то новое вне
  `last_tool_result`, это нужно явно добавить в сообщение.
- `last_tool_result` не обрезается: id из него нужны для отчёта.
