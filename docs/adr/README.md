## Как писать ADR

- Новое решение — новый файл `NNNN-<slug>.md` со следующим номером и строка
  в таблице выше. Пишем по-русски, как и остальные `docs/`.
- Принятый ADR по существу не переписываем. Если решение меняется, пишем
  новый ADR, а у старого ставим статус «Заменено [NNNN](…)».
- Гипотезы, которые ещё проверяем (роли, стек, модели), остаются в
  [architecture.md](../architecture.md#гипотезы). ADR появляется, когда
  выбор сделан.
- ADR короткий: сравнение вариантов — по существу, без таблиц ради таблиц.

```markdown
# NNNN. Заголовок

- Статус: Предложено | Принято | Устарело | Заменено [NNNN](NNNN-….md)
- Дата: ГГГГ-ММ-ДД
- Источник: PR, коммит или обсуждение

## Контекст
Какая ситуация и какие силы действуют.

## Решение
Что делаем.

## Рассмотренные варианты
Что ещё было и почему не выбрали.

## Последствия
Что стало проще, что сложнее, что пересмотреть.
```
