# 0008. JSONL-трейсы вне репозитория

- Статус: Принято
- Дата: 2026-10-05
- Источник: PR #2, коммиты a206795, 5df5edc

## Контекст

На арене одну задачу повторить нельзя, поэтому разбирать её можно только по
записи. Правила запрещают публиковать задачи и решения, а большие дампы
раздувают контекст сессий разработки.

## Решение

Каждая задача пишет JSONL-трейс в `$TRACE_DIR` (по умолчанию
`~/.local/share/sibyl_h0und/traces/`), одно событие на строку: плоские поля
для `jq`, visidata и DuckDB и сырые данные в `payload`. Ответы runtime
сохраняются целиком. Ошибка записи трейса не прерывает run. Своего
просмотрщика нет, хватает готовых инструментов. В репозитории — не больше
1–2 обезличенных задач в `tests/fixtures/`.

## Рассмотренные варианты

- Хранить трейсы в репозитории: нарушает правила и раздувает контекст.
- Отдельный `run.json` и git-ревизия: убраны как лишние, настройки run'а
  лежат в `task_start`.

## Последствия

- Офлайн-проигрывание (`scripts/replay_flags.py`) работает по трейсам, но
  видит только узлы, которые открыл записанный агент.
- Формат событий описан в [development.md](../development.md#трейсы), при
  его изменении старые трейсы должны читаться.
