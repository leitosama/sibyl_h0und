# 0016. Investigation собирает ответ модели, trace владеет форматом событий

- Статус: Принято
- Дата: 2026-10-06
- Источник: [issue #29](https://github.com/leitosama/sibyl_h0und/issues/29), кандидаты 1 и 2; нужно задачам #20–#24

## Контекст

`_investigate` в `agent.py` вручную связывал каталог, GraphLedger, FlagBoard,
историю и трейс. Правила превращения ответа runtime в сообщение для модели
(`still_open`, `flags`, кэш, ошибки) проверялись только через весь агент с
файлами трейса. Формат событий знали четыре места: агент и `llm.py` писали его,
`replay._read_call` читал, `test_replay.write_trace` собирал по-своему. Replay
заново реализовал обработку ответа (разбор JSON, пропуск ошибок, `rank_flags`) и
уже расходился с агентом. Каждый новый источник знаний (#20–#24) добавлял код
в оба места.

## Решение

- `Investigation` (`investigation.py`) владеет каталогом, GraphLedger,
  FlagBoard, слиянием `still_open` и `flags`, текстом локальных ответов и
  событиями этих решений. Две операции: `before_call(tool, arguments,
  finish_only)` возвращает `LocalAnswer` или `Send`, `after_call(tool,
  arguments, outcome)` возвращает сообщение для модели и показанные находки.
  `LedgerDecision` и ключи feedback наружу не выходят.
- `ToolOutcome` (`outcome.py`) разбирает ответ runtime один раз: так же для
  живого ответа и для записанного. Награда шага в нём отсутствует (ADR 0006).
- `trace.py` владеет форматом: `TaskTrace` пишет каждый `kind` типизированным
  методом и прячет счётчики за методами, `read_task` читает события обратно.
  Формат не меняется, старые трейсы читаются (ADR 0008).
- Replay пропускает записанные ответы через `Investigation.after_call`, так что
  `--compare` видит то, что видела бы модель. Кэш replay теперь хранит задачу и
  вызовы (`tasks-v3`), помнит каталог трейсов и число файлов, а каталог трейсов
  по умолчанию берётся как у агента.

## Рассмотренные варианты

- Оставить цикл как есть и вынести только помощники: правила сборки сообщения
  остались бы в агенте, replay продолжал бы копировать их.
- Хранить в кэше replay только результаты: тогда `after_call` не получает
  аргументы вызовов и каталог, и реплей перестаёт совпадать с агентом.

## Последствия

- Тесты правил сборки сообщения синхронные и не трогают файлы
  (`tests/test_investigation.py`); тест агента проверяет только цикл.
- Круговой тест (агент пишет трейс, replay его читает) закрепляет совместимость
  с ADR 0008.
- Меняя форму ответа runtime или событие трейса, правим один модуль.
- Кэш `tasks-v2` не читается, при первом запуске он пересобирается.
