# 0009. Run на арене не ждёт ни человека, ни провайдера

- Статус: Принято
- Дата: 2026-10-05
- Источник: PR #5, коммиты 2af42bd, 4a897d3; architecture.md

## Контекст

Окно зачёта жёсткое: по правилам 40 задач за 4 часа (организаторы обещали
уточнить интервал), и задачи, до которых агент не дошёл, баллов не получают.
Сейчас задача занимает у нас в среднем около 6 минут — это наш замер, а не
лимит. На run'е `practice` 3165c343 6 из 30 задач
прервались с нулём: пять — из-за проверки флага `task_completed`, который
агент не читает, одна — из-за кратковременного HTTP 400 от прокси Open
WebUI. Ретрай всех ошибок подряд тратил по 17 секунд и 3 запроса на каждую
постоянную ошибку.

## Решение

- Запуск на арене никогда не ждёт человека. Отладочные режимы (пошаговый,
  человек в цикле) работают только на записанных задачах, без runtime.
- Повторяем только временные ошибки LLM: соединение, 409, 429, 5xx и 400 с
  ошибкой прокси. Паузы 2, 5 и 10 секунд, таймаут повторяем один раз.
  Постоянные ошибки (400 по длине контекста, 401, 403, 404, 422) всплывают
  сразу. Каждый сбой пишется в трейс как `llm_error`.
- Не прерываем задачу из-за полей ответа модели, которые агент не
  использует.

## Рассмотренные варианты

- Бесконечные повторы: run может зависнуть до автозакрытия через 15 минут.
- Без повторов: одна вспышка у провайдера стоит задачи.

## Последствия

- Отладку конкретной задачи делаем офлайн по трейсу.
- Время LLM в трейсе меряется только по успешному запросу.
