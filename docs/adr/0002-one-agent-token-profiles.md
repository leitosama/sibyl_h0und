# 0002. Один агент, токены — профили окружения

- Статус: Принято
- Дата: 2026-10-04
- Источник: PR #1, коммит f896609

## Контекст

Сначала были две консольные команды `h0und1` и `h0und2` с одинаковым кодом.
На деле это не разные агенты, а разные токены runtime: у каждого токена своя
статистика и свои лимиты на run'ы. Для зачёта 10 октября нужна статистика с
чистого листа.

## Решение

Одна команда `h0und`. Токен, провайдер LLM и арена задаются профилем:
`.env.h0und2` для разработки и бенчей, `.env.h0und1` для зачёта. Запуск
только с `uv run --env-file <профиль> h0und`. В профиле зачёта арену задаём
явно: 10 октября открыта и `practice`.

## Рассмотренные варианты

- Отдельная команда на токен: дублирует код и прячет, что различаются только
  настройки.

## Последствия

- Профили `.env*` (кроме `.env.example`) не коммитятся.
- `--env-file` обязателен: gRPC читает `GRPC_DNS_RESOLVER` из окружения
  процесса.
