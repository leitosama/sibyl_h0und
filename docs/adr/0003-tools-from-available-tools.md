# 0003. Инструменты строим только из `available_tools`

- Статус: Принято
- Дата: 2026-10-04
- Источник: competition.md, architecture.md, PR #13

## Контекст

Задача приносит в `observation` поле `available_tools`: JSON со списком
инструментов и схемами их аргументов. Организаторы предупредили, что на
зачёте набор инструментов и контекст могут отличаться от `practice`. Базовый
агент зашивал инструменты в `models.py`.

## Решение

`available_tools` — единственный источник истины об инструментах. Каталог
передаётся модели из задачи, вызов инструмента, которого нет в каталоге,
отклоняется локально и в runtime не уходит. Задача без
`finish_investigation` в каталоге — ошибка.

## Рассмотренные варианты

- Захардкоженные pydantic-схемы инструментов: строже валидация, но агент
  ломается или молчит, если на зачёте инструмент переименуют или добавят.

## Последствия

- Логика, завязанная на конкретный инструмент (например, `search`), должна
  переживать его отсутствие.
- Схемы инструментов в `models.py` не должны ограничивать модель: там
  остаются только оболочка шага и то, что читает наш код (отчёт
  `finish_investigation`).
- Выполнено: схема шага строится из каталога каждой задачи, см.
  [0014](0014-step-schema-from-catalog.md).
