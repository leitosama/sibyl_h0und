# 0018. Пустой отчёт отклоняется локально один раз

- Статус: Принято
- Дата: 2026-10-07
- Источник: [issue #9](https://github.com/leitosama/sibyl_h0und/issues/9), run `practice` `43acad6a`

## Контекст

На run'е `43acad6a` две самые длинные задачи (33 и 35 ходов, контекст
70–93 тыс. токенов) закончились отчётом-заглушкой: `benign` с пустым
`reasoning` и без `legitimacy_evidence`, `malicious` с `reasoning` «Short
test» и одним артефактом. Ответ не обрезан: в том же сообщении модель
планирует продолжать расследование, а инструментом выбирает
`finish_investigation`. Runtime такой отчёт принимает, задача кончается, и
ошибку уже не исправить.

## Решение

- Перед отправкой `finish_investigation` агент ищет отчёт: сами аргументы
  или объект прямо внутри них, у которого есть `verdict`. Отчёт пустой, если
  `reasoning` короче 20 символов или пуст список, который нужен вердикту
  (`ir_artifacts` для `malicious`, `legitimacy_evidence` для `benign`).
- Пустой отчёт отклоняется локально **один раз за задачу**: модель получает
  ошибку и сдаёт отчёт заново. Следующий отчёт уходит в runtime как есть,
  даже если он снова пустой, в том числе в режиме «только отчёт».
- Отказ пишется в трейс событием `report_refused`.
- Вызова runtime отказ не тратит. Вердикт, состав артефактов и качество
  текста агент не оценивает.

## Рассмотренные варианты

- Отклонять, пока отчёт не станет полным: в режиме «только отчёт» у модели
  5 ходов (ADR 0015), и упорная модель исчерпает их, а задача прервётся с
  `Q = 0`. Это нарушает ADR 0009: задачу не прерываем из-за полей ответа,
  которые агент не использует. Слабый отчёт лучше никакого.
- Порог «настоящего» отчёта (80 символов и больше): режет краткие, но
  верные отчёты, а длину текста грейдер не оценивает.
- Собирать отчёт отдельным запросом с коротким контекстом (роль
  IR-аналитика): лечит причину, но меняет ADR 0007 и требует отдельного
  решения.

## Последствия

- Заглушка в конце длинного расследования получает второй шанс за один ход
  LLM.
- Порог 20 символов и правило «один раз» выбраны по двум случаям одного
  run'а. Как часто срабатывает отказ, видно по `report_refused` в трейсах.
