# 0022. Benign-вердикт оспаривает челленджер на дайджесте улик

- Статус: Принято
- Дата: 2026-10-09
- Источник: [issue #45](https://github.com/leitosama/sibyl_h0und/issues/45), дизайн [finish-gate.md](../finish-gate.md); развивает [0020](0020-alert-presumed-malicious.md), дополняет [0007](0007-compact-llm-context.md)

## Контекст

Вопрос ADR 0020 срабатывает, но вердикт не меняет. На двух прогонах
`practice` от `5abff94` (8 октября, по 30 задач) из 11 (DeepSeek-V4-Flash) и
16 (Qwen3.8-27B) оспоренных benign ни один не перевернулся, а неверные benign
остались неверными. Решающий факт в этих задачах уже был в заметках модели:
ошибка в выводе («подписанный бинарь, обычный родитель — benign»). На
открытый вопрос «почему сработала детекция?» легко ответить, повторив вердикт:
модель делает 0–2 вызова и сдаёт тот же отчёт.

## Решение

- Первый `benign`-отчёт вне режима «только отчёт» (те же условия, что в
  ADR 0020) сначала уходит **челленджеру** — отдельному вызову той же LLM с
  чистым контекстом.
- Челленджер видит алерт, каталог runtime-инструментов (без
  `finish_investigation` и локальных), **дайджест улик** и `still_open`.
  Отчёта, рассуждений и состояний головы он не видит.
- Дайджест строит код из GraphLedger (`digest.py`): каждый объект, который
  вернул runtime, один раз, со всеми свойствами; объекты сгруппированы по
  ближайшей хост-сущности (тип `host`), связи между разными хостами —
  отдельным блоком, остальное — в `no_host`; порядок — обход в ширину от
  объектов алерта. У сущности вместо списков связей — `unvisited_relation_ids`.
  Если хостов в графе нет или тип назван иначе, всё попадает в `no_host` в
  порядке обхода. Дайджест не выбирает «важные» свойства (ADR 0017).
- Челленджер строит самую сильную версию атаки по тем же фактам и даёт 1–3
  проверки: вызов инструмента и результат, который версию опровергнет.
  Ответ валидируется строгой схемой, которую строит `ToolCatalog` из
  каталога задачи (ADR 0003, 0014).
- Код оставляет только применимые проверки: инструмент из каталога,
  аргументы по его схеме, id, которые вернул runtime (ADR 0005). Повтор уже
  сделанного вызова помечается `already_made`. Голова получает версию,
  проверки и `still_open` локальным ответом на `finish_investigation` и
  решает сама: делает проверки (повторы отвечаются из кэша) или сдаёт отчёт
  снова. Следующий отчёт уходит в runtime как есть.
- Если челленджер упал после обычных повторов, вернул негодный ответ или не
  дал ни одной применимой проверки, голова получает общий вопрос ADR 0020.
  Задача на этом шаге не останавливается (ADR 0009).
- Пустой benign-отчёт (ADR 0018) по-прежнему получает один отказ с общим
  вопросом, без челленджера.
- `malicious` не оспаривается: противоположная версия для него — «правдоподобная
  задача администратора», то самое ленивое объяснение, из-за которого
  ошибаются benign.
- Промпт челленджера — из общих принципов, без программ, портов, типов связей
  и сценариев из трейсов `practice`. `reward` не используется (ADR 0006).
- `Investigation` остаётся владельцем локальных ответов (ADR 0016):
  `before_call` возвращает `Review` с запросом побочного хода, цикл агента
  только выполняет его и отдаёт ответ в `after_review`.
- Трейс: у `llm_call` новое поле `role` (`head` или `challenger`), у
  `benign_challenged` — поле `fallback` (причина или `null`), версия и
  проверки — в `feedback`. Только новые поля (ADR 0008).

## Рассмотренные варианты

- Оставить общий вопрос: на данных выше он ни разу не перевернул вердикт.
- Давать челленджеру историю головы: он закрепляется на её выводе, а
  длинный контекст (70–93 тыс. токенов) сам ухудшает ответы.
- Выполнять проверки челленджера кодом: это решение за модель и лишние
  вызовы runtime там, где голова может ответить из уже собранного.
- Отклонять benign, пока проверки не сделаны: упорная модель исчерпает ходы
  (ADR 0009, 0018).
- Структурные поля фаз и гипотез в шаге
  ([issue #35](https://github.com/leitosama/sibyl_h0und/issues/35)): цена в
  токенах на каждом ходу, а ошибка — только в фазе решения.

## Последствия

- Один лишний вызов LLM на первый benign задачи; вызовов runtime челленджер
  не тратит, но голова может сделать по его проверкам 1–3 вызова.
- Челленджер может перевернуть и верный benign. Перевороты в обе стороны
  смотрим на `practice` против `20261008T150601Z`; офлайн-стенд
  `scripts/replay_side_turn.py` гоняет только челленджер по трейсам, с
  разбиением на dev и holdout по хешу id задачи.
- Дайджест — общая часть с будущим репортёром
  ([issue #39](https://github.com/leitosama/sibyl_h0und/issues/39)).
