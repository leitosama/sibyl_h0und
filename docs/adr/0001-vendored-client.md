# 0001. Клиент и схема организаторов не правим

- Статус: Принято
- Дата: 2026-10-04
- Источник: PR #1, коммит 0d9178e

## Контекст

Проект начат с базового агента организаторов. В нём есть gRPC-схема runtime
(`proto/`) и клиент `src/bluesec1_client/`: idempotency key, `call_id`,
повторы и разбор ошибок. Организаторы могут обновить схему и клиент, и
обновление должно ложиться без конфликтов.

## Решение

`proto/` и `src/bluesec1_client/` — вендорная копия, руками её не правим.
Сгенерированный код `src/bluesec1_client/proto/` обновляем только скриптом
`scripts/generate_remote_proto.py`. Поведение поверх клиента пишем обёрткой
в `src/sibyl_h0und/`.

## Рассмотренные варианты

- Править клиент на месте: быстрее для мелочей, но каждое обновление от
  организаторов превращается в ручное слияние.

## Последствия

- Обновление клиента — замена каталога и перегенерация.
- Если клиенту чего-то не хватает, это видно как обёртка в нашем коде, а не
  как незаметная правка чужого.
