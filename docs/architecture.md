# Архитектура

Как устроен агент сейчас, свод правил и открытые гипотезы. Почему правило
такое — в его ADR ([список](adr/README.md)), правила соревнования — в
[competition.md](competition.md). Здесь решения не расписываем: принятое
уходит в ADR, а сюда — одна строка со ссылкой.

## Агент и токены

Агент один: команда `h0und`, код в `src/sibyl_h0und/`. Под `h0und1` и `h0und2`
понимаются токены runtime. Токенов можно получить сколько угодно, у каждого
своя статистика и свои лимиты (run'ы, задачи), подробнее в
[competition.md](competition.md#арена-и-run).

| Токен | Профиль | Когда |
| --- | --- | --- |
| `h0und2` | `.env.h0und2` | разработка и бенчи до 10 октября |
| `h0und1` | `.env.h0und1` | зачёт 10 октября, статистика с чистого листа |

Режимы отладки (полная трассировка, пошаговый режим, человек в цикле)
включаются флагами и работают только на записанных задачах, без runtime. На
арене одну задачу повторить нельзя, поэтому отлаживаемся офлайн.

## Код

```
proto/                         gRPC-схема runtime (от организаторов)
scripts/generate_remote_proto.py  перегенерация src/bluesec1_client/proto/
scripts/build_*_pack.py        сборка пакетов знаний из upstream-источников
scripts/replay_knowledge.py    какие источники знают сущности из сохранённых трейсов
scripts/replay_side_turn.py    офлайн-стенд челленджера и репортёра по сохранённым трейсам
src/bluesec1_client/           клиент runtime — копия от организаторов, НЕ ПРАВИМ
src/sibyl_h0und/
  cli.py                       точка входа h0und: настройки, run, печать итогов
  settings.py                  настройки из окружения / .env
  agent.py                     SimpleSGRAgent: цикл «одно действие за ход», SYSTEM_PROMPT
  investigation.py             Investigation: before_call / after_call / after_review одной задачи (ADR 0016), промпты челленджера, его постановления и репортёра
  digest.py                    дайджест улик из GraphLedger для побочных ходов (ADR 0022)
  outcome.py                   ToolOutcome: ответ runtime, разобранный один раз
  llm.py                       клиент OpenAI-совместимого API со structured output
  catalog.py                   ToolCatalog: каталог задачи и строгая схема шага из него
  budget.py                    CallBudget: страховочный лимит вызовов runtime, режим «только отчёт»
  models.py                    оболочка шага (NextStep, ToolCall), схемы аргументов practice
  ledger.py                    GraphLedger: известные id, кэш вызовов, проверка finish
  vocabulary.py                словарь знаний и инструмент lookup_knowledge (ADR 0017)
  nextron.py                   строки шпаргалки Nextron: Location / User Context / Form
  normalize.py                 общая нормализация: имя программы, командная строка, путь, домен
  knowledge/                   пакеты знаний: JSON-снимки внешних источников и NOTICE
  trace.py                     JSONL-трейсы вне репозитория: запись и чтение событий
  replay.py                    офлайн-покрытие словаря по сохранённым трейсам
  side_replay.py               офлайн-стенд побочных ходов: трейс до нужного отчёта, только этот ход
tests/                         тесты без сети
```

Цикл агента: на каждом шаге модель возвращает `NextStep` (состояние, план,
один вызов инструмента) по строгой JSON-схеме, которую `ToolCatalog` строит
из `available_tools` задачи. `Investigation.before_call` проверяет вызов по каталогу задачи и в
GraphLedger, в runtime уходит только то, что нельзя ответить локально, а
`after_call` собирает ответ для модели: `last_tool_result` вместе с
`still_open`. Вызов `lookup_knowledge` отвечает локально из пакетов знаний.
Первый benign-отчёт `before_call` превращает в `Review`: цикл агента
выполняет побочный ход челленджера, а `after_review` собирает из его ответа
локальный ответ модели. Следующий отчёт снова уходит челленджеру, и вердикт
выносит он; отчёт под этот вердикт пишет репортёр. Задача заканчивается, когда `finish_investigation`
возвращает `task_result`.

## Правила

| Правило | ADR |
| --- | --- |
| Клиент `src/bluesec1_client/` и `proto/` не правим, поведение поверх — обёрткой в `sibyl_h0und` | [0001](adr/0001-vendored-client.md) |
| Один агент, токены — профили `.env.*`, запуск только с `--env-file` | [0002](adr/0002-one-agent-token-profiles.md) |
| Инструменты строим только из `available_tools`, схема шага — из каталога задачи | [0003](adr/0003-tools-from-available-tools.md), [0014](adr/0014-step-schema-from-catalog.md) |
| Экономим вызовы без бюджета шагов; страховочный лимит — 95 вызовов runtime, у лимита остаётся только `finish_investigation` | [0004](adr/0004-call-economy-without-step-budget.md), [0015](adr/0015-runtime-call-ceiling.md) |
| GraphLedger отвечает локально на выдуманные id и повторы и проверяет `finish_investigation` | [0005](adr/0005-graph-ledger.md) |
| Пошаговый `reward` runtime — только для офлайн-разбора | [0006](adr/0006-step-reward-offline-only.md) |
| Модель получает алерт и каталог один раз, дальше только новые улики | [0007](adr/0007-compact-llm-context.md) |
| JSONL-трейсы пишем вне репозитория, старые трейсы должны читаться | [0008](adr/0008-traces-outside-repo.md) |
| Run на арене не ждёт ни человека, ни провайдера; повторяем только временные ошибки LLM | [0009](adr/0009-run-never-stalls.md) |
| Знания — словарь, который модель читает через `lookup_knowledge`; правил-детекторов и уровней нет | [0017](adr/0017-knowledge-as-vocabulary.md) |
| Знания — закоммиченные JSON-снимки, агент и CI в сеть не ходят | [0012](adr/0012-knowledge-packs.md) |
| В отчёт попадает только то, что относится к инциденту | [0013](adr/0013-minimal-report.md) |
| Алерт считаем атакой, пока улики не докажут обратное; benign-вердикт перед отправкой один раз возвращается модели на проверку | [0020](adr/0020-alert-presumed-malicious.md) |
| Первый benign оспаривает челленджер: отдельный вызов LLM на дайджесте улик, без рассуждений головы; при сбое — общий вопрос; модель — `LLM_CHALLENGER_MODEL` или общая | [0022](adr/0022-benign-challenger.md), [0025](adr/0025-challenger-model.md) |
| После челленджа benign-вердикт выносит челленджер по своим проверкам; голова только собирает улики; без постановления остаётся вердикт черновика | [0027](adr/0027-challenger-rules-the-verdict.md) |
| Отчёт в runtime пишет репортёр на дайджесте улик при фиксированном вердикте (головы или постановления); негодный отчёт — один ремонт, потом черновик | [0023](adr/0023-reporter.md), [0027](adr/0027-challenger-rules-the-verdict.md) |

## Гипотезы

Это не решения, а то, что проверяем на `practice`. Когда выбор сделан, он
уходит в ADR, а сюда — строка в [правилах](#правила). Стек и роли выбираем по
трейсам: `total_reward`, `tool_calls`, шаги и время на задачу.

Кандидат в стек — **PydanticAI** поверх OpenAI-совместимых endpoint'ов. Если
переходим на него, отключаем значения по умолчанию, которые противоречат
правилам: лимит запросов `UsageLimits(request_limit=50)` (см.
[0004](adr/0004-call-economy-without-step-budget.md)) и параллельное
выполнение нескольких tool calls из одного ответа модели (дубли проходят мимо
GraphLedger). Альтернатива — развивать свой цикл, он уже даёт полный контроль
над вызовами.

Кандидаты в модели: GLM-5.3 через API провайдера, локальная DeepSeek v4.1
Flash, OpenRouter для экспериментов.

### Роли

```
                ┌──────────────────────────── задача (алерт + available_tools)
                ▼
        ┌───────────────┐   runtime-тулы (search / get_* / finish_investigation)
        │  Голова       │──────────────────────────────────────────► runtime
        │  (judge)      │◄──── ответы ───┐
        └──────┬────────┘                │
               │ поручения               │ GraphLedger: пройденные узлы и связи,
               ▼                         │ кэш ответов, запрет повторов
   ┌──────────┬──────────┬──────────┐    │
   │Гипотезёр │IR-аналит.│   TI     │ ───┘ работают только с уже собранными
   └──────────┴──────────┴──────────┘      уликами и внешними знаниями
               │
               ▼
     MCP (VirusTotal и др.), RAG по плейбукам, MITRE ATT&CK, LOLBAS/GTFOBins
```

- **Голова** берёт задачу, единственная ходит в runtime-инструменты и выносит
  вердикт. Так весь бюджет вызовов в одних руках.
- **Исполнители** — роли без доступа к runtime:
  - гипотезёр предлагает версии, что произошло и куда смотреть дальше;
  - IR-аналитик собирает `ir_artifacts` и `legitimacy_evidence` (отбор
    артефактов, см. [0013](adr/0013-minimal-report.md));
  - TI обогащает индикаторы через MCP и базы знаний.
  Состав ролей будет меняться по результатам практики.
- Первые две роли проектируем как шлюз отчёта: челленджер (гипотезёр) на
  benign-вердикт и репортёр (IR-аналитик) на каждый отчёт, оба на дайджесте
  улик из GraphLedger, см. [finish-gate.md](finish-gate.md). Челленджер
  принят ([0022](adr/0022-benign-challenger.md)), репортёр тоже
  ([0023](adr/0023-reporter.md)).

### Знания и детекторы

- Open-source плейбуки по типам инцидентов и TI-данные лежат локально в
  векторном хранилище (какое — пока не выбрано). Доступ к внешним сервисам —
  через свои MCP-серверы.
- Правила-детекторы по командной строке, типам связей и сети — источники для
  ошибочных benign, см. [wrong-patterns.md](wrong-patterns.md) и
  [0011](adr/0011-nextron-as-ti.md).

### Время

Сейчас задача занимает у нас в среднем около 6 минут (см.
[0009](adr/0009-run-never-stalls.md)). Каждая дополнительная роль добавляет
вызовы LLM на шаге, поэтому состав ролей выбираем с учётом замеров времени.
